# Discord Forum Collector — v4

Запуск из корня репозитория:

```bash
python v4/discord_forum_gui.py
```

v4 сохраняет одну вкладку и обрабатывает публикации последовательно. Для каждого открытого результата опроса сборщик сохраняет список активного варианта и переключает все остальные варианты с ненулевым счётчиком — не только «За». Варианты с нулём голосов отмечаются как пропущенные.

Разбор приложенного `Лог.jsonl` выявил причину пропавших результатов: для части вариантов сборщик уже находил имена (например, 1 строку для «Против» и «Воздержался»), но затем нажимал отдельный «Просмотреть опрос». Этот контрол открывал постороннее меню; последующая обработка `None` приводила к `NoneType is not iterable` и срывала сохранение всей публикации. В v4 такие `View Poll` контролы не нажимаются, а пустые списки обрабатываются безопасно, поэтому найденные результаты не теряются из-за этой ошибки.

После клика сборщик ждёт появления видимых строк, затем собирает и прокручивает список. В JSONL сохраняются число строк по каждому варианту, ожидаемый счётчик, совпадение счётчика и диагностика ожидания. Также исправлено предупреждение Python о неэкранированном `\s`.

Сбор ограничен данными, которые Discord действительно показывает залогиненному пользователю. Скрытые данные не извлекаются.
